# ROS 2 Humble 三轮全向底盘建图导航总实施方案

> 系统：Ubuntu 22.04 + ROS 2 Humble
> 底盘：三轮 Kiwi、M3508 + C620、RoboMaster 开发板 C 型
> 主雷达：Livox Mid-360S（主路线）
> 备用雷达：Pacecat LDS-E110-R（保留二维路线）
> 更新日期：2026-08-07

## 1. 当前结论

当前代码已经完成底盘 USB 控制、三轮正逆运动学、底盘原始数据发布、Mid-360S 驱动封装、
FAST-LIO2 三维建图入口和 Pace 二维建图备用入口。系统按“硬件层、状态估计层、建图层、
导航层、任务层”解耦，切换雷达或 IMU 只替换 launch/YAML，不修改底盘驱动。

当前可用能力：

```text
[完成] 键盘/Nav2 Twist -> 三轮电机目标速度 -> USB 0x3A
[完成] USB 0x3B -> 三电机、欧拉角、角速度、加速度
[完成] 原始轮式 odom、底盘 IMU、关节状态、底盘调试话题
[完成] 轮速 + 可选 IMU 的 robot_localization 平面 EKF
[完成] Mid-360S 原始点云/IMU -> FAST-LIO2 三维点云地图
[完成] Pace E110 /scan -> SLAM Toolbox -> 二维 /map
[待做] Mid-360S 三维地图到二维 OccupancyGrid 的投影
[待做] LIO 定位到 map -> odom 的唯一 TF 适配
[待做] Nav2、AMCL/LIO 定位模式和任务层闭环
```

因此，Mid-360S 已支持三维建图，但还不能把 `/Laser_map` 直接当成 Nav2 的二维 `/map`。
Pace 备用路线目前能直接产生二维 `/map`，可先用于 Nav2 基线验证。

## 2. 分层架构

```text
任务层
  └─ mission_manager / Nav2 Simple Commander / 行为树

导航层
  ├─ planner_server：SmacPlanner2D 或 NavFn
  ├─ controller_server：第一阶段 DWB，后续 MPPI Omni
  ├─ behavior_server / bt_navigator
  ├─ velocity_smoother / collision_monitor
  └─ /cmd_vel_safe

建图与定位层
  ├─ 主路线：Mid-360S + FAST-LIO2 + 二维地图投影 + LIO TF 适配
  └─ 备用路线：Pace E110 + SLAM Toolbox；导航时 map_server + AMCL

状态估计层
  └─ robot_localization EKF
       ├─ /chassis/odom/raw
       └─ /livox/imu/ekf 或 /chassis/imu/data_raw（由 YAML 二选一）

底盘驱动层
  └─ kiwi_base_node
       ├─ Twist 限幅和 Kiwi 逆解
       ├─ USB 0x3A/0x3B + CRC8/CRC16
       ├─ Kiwi 正解和轮速积分
       └─ 底盘原始话题

下位机层
  └─ RoboMaster C：USB CDC、M3508 速度 PID、C620 CAN、BMI088
```

边界原则：

1. `kiwi_base` 不依赖雷达、SLAM 或 Nav2；
2. 底盘 IMU 和 Mid-360S IMU 始终分话题发布，不互相覆盖；
3. EKF 输入源只在 YAML 选择；
4. 安装外参只在 URDF/Xacro 维护；
5. `odom -> base_footprint` 只允许 EKF 发布；
6. 建图/定位模块只负责 `map -> odom`；
7. 速度指令只通过 `/cmd_vel_safe` 进入底盘。

## 4. 底盘控制链路

### 4.1 机械参数

```text
轮子直径                   0.203 m
轮子半径 R                 0.1015 m
底盘圆心到轮心距离 L       0.32256 m
M3508 减速比               19:1
额定电压                   24 V
持续最大扭矩               3 N·m
3 N·m 下最大转速           469 rpm
C620 最大持续电流          20 A
```

硬件和运动学参数只维护在 `src/kiwi_base/config/kiwi_base.yaml`。URDF 通过 Xacro 读取同一
轮径和轮心距，避免模型与控制分别硬编码。

### 4.2 坐标和逆运动学

ROS 坐标：`+x` 前进、`+y` 左移、`+z/+wz` 逆时针。三轮输出轴速度：

```text
w1 = ( sin60*vx + 0.5*vy - L*wz) / R
w2 = (            -vy - L*wz) / R
w3 = (-sin60*vx + 0.5*vy - L*wz) / R
```

`w1/w2/w3` 是轮输出轴 `rad/s`。0x3A 发送前分别乘 19，得到三个 M3508 转子轴目标速度。
正运动学使用以上公式的解析逆变换，不再维护另一套 Jacobian 参数。

历史通用 Jacobian、伪逆、重复有限值检查和二次轮速限幅仍用 `//` 注释保留，并标注停用
原因，不参与编译。输入有限值处理和速度限幅集中在 Twist 入口，避免多处改变控制比例。

### 4.3 USB 协议

```text
字节 0      SOF/版本  0x33
字节 1      payload 长度
字节 2      数据 ID
字节 3      CRC8（覆盖前 3 字节）
字节 4..N   payload，小端 float32
末尾 2 字节 CRC16，小端
```

上位机下发：`ID=0x3A`、payload 12 字节、三个电机转子轴目标 `float32 rad/s`。
下位机回传：`ID=0x3B`、payload 48 字节、12 个 `float32`：

```text
0..2   motor_1/2/3_actual_rad_s
3..5   roll/pitch/yaw_rad
6..8   gyro_x/y/z_raw_rad_s
9..11  accel_x/y/z_m_s2
```

上位机协议层负责粘包、半包、SOF 搜索、长度、CRC8、CRC16 和有限浮点数检查。下位机继续
负责 M3508 PID 和 CAN 电调控制。

## 5. 话题和消息契约

```text
话题                         消息类型                              数据归属
/cmd_vel_safe                geometry_msgs/msg/Twist               底盘安全速度入口
/chassis/feedback/raw        kiwi_base/msg/FeedbackDebug           C 板 0x3B 原始 12 字段
/chassis/imu/data_raw        sensor_msgs/msg/Imu                   C 板 BMI088 数据
/chassis/odom/raw            nav_msgs/msg/Odometry                轮速原始里程计
/joint_states                sensor_msgs/msg/JointState           三轮关节数据
/livox/lidar                 livox_ros_driver2/msg/CustomMsg       Mid-360S 原始点云
/livox/imu                   sensor_msgs/msg/Imu                   Mid-360S 原始 IMU
/livox/imu/ekf               sensor_msgs/msg/Imu                   Mid-360S EKF 适配支路
/odometry/filtered           nav_msgs/msg/Odometry                平面 EKF 输出
/cloud_registered            sensor_msgs/msg/PointCloud2          LIO 世界系配准点云
/Laser_map                   sensor_msgs/msg/PointCloud2          LIO 三维地图
/Odometry                    nav_msgs/msg/Odometry                LIO 三维位姿
/scan                        sensor_msgs/msg/LaserScan             Pace SLAM 输入
/map                         nav_msgs/msg/OccupancyGrid           Pace 二维地图
```

### 5.1 `FeedbackDebug`

每个值拆成独立 `float32`，Foxglove 可直接选择曲线。电机、欧拉角、原始角速度、原始加速度
均保持 0x3B 顺序。字段说明直接维护在 `src/kiwi_base/msg/FeedbackDebug.msg`。

### 5.2 `sensor_msgs/Imu`

```text
header                  采样/接收时间和传感器 frame_id
orientation             四元数；Livox 无姿态时明确标记不可用
orientation_covariance  姿态 3x3 协方差
angular_velocity        三轴角速度 rad/s
angular_velocity_covariance 角速度 3x3 协方差
linear_acceleration     三轴线加速度 m/s^2
linear_acceleration_covariance 加速度 3x3 协方差
```

底盘 IMU 的角速度按 YAML 转换为 ROS 右手系并应用静止死区；`/chassis/feedback/raw` 仍保留
下位机未修正数值。Mid-360S `/livox/imu` 保持驱动原值，适配节点只复制数据、补协方差和
可选死区，输出 `/livox/imu/ekf`。

### 5.3 `nav_msgs/Odometry`

`pose` 是位置和四元数，`twist` 是线速度和角速度，两者各带 6x6 协方差。
`/chassis/odom/raw` 的 `pose` 是轮速积分调试量，EKF 只融合其中 `vx/vy/wz`；
`/odometry/filtered` 是底盘局部里程计；`/Odometry` 是 FAST-LIO2 三维位姿。

### 5.4 Livox `CustomMsg`

包含 `header`、`timebase`、`point_num`、`lidar_id` 和 `points[]`。每个点包含逐点
`offset_time`、`x/y/z`、反射率、tag 和扫描线。FAST-LIO2 依赖逐点时间进行运动去畸变，
不能把主路线随意改成缺少时间字段的普通点云。

## 6. TF 与外参

唯一 TF 目标：

```text
map                         建图/定位模块发布
└── odom                    EKF world_frame
    └── base_footprint      EKF 发布动态 TF
        └── base_link       URDF 固定 TF
            ├── chassis_imu_link
            ├── lidar_link
            │   └── livox_frame
            └── 三个 motor_link -> wheel_link
```

安装外参统一维护在 `src/kiwi_slam/urdf/kiwi.urdf.xacro`：

```text
C 板 IMU：x=-0.0115 m，y=+0.149 m，z=0；相对 base_link yaw=pi（统一坐标旋转后的值）
Mid-360S：z=0.20 m；相对 base_link yaw=pi，x/y 仍需实测标定
```

FAST-LIO2 的 `extrinsic_T/R` 是 Mid-360S 内部点云原点到内置 IMU 的厂内标定，不属于
整机安装外参。FAST-LIO2 原生 TF 当前重映射到 `/fast_lio/tf`，防止抢占底盘 TF。

## 7. EKF 传感器选择

### 7.1 Mid-360S 主路线

`src/kiwi_slam/config/ekf_mid360.yaml`：

```text
odom0 = /chassis/odom/raw   融合 vx、vy、wz
imu0  = /livox/imu/ekf      融合 angular_velocity.z
输出  = /odometry/filtered + odom -> base_footprint
```

FAST-LIO2 同时直接使用 `/livox/imu`，与平面 EKF 支路并行。

### 7.2 Pace/底盘备用路线

`src/kiwi_base/config/ekf_chassis.yaml`：

```text
odom0 = /chassis/odom/raw       融合 vx、vy、wz
imu0  = /chassis/imu/data_raw   融合 yaw、angular_velocity.z
输出  = /odometry/filtered + odom -> base_footprint
```

两套 EKF 配置不能同时启动，否则会重复发布相同节点名、话题和 TF。

## 8. 建图与导航路线

### 8.1 Mid-360S 主路线

1. `livox_ros_driver2` 发布原始点和 IMU；
2. FAST-LIO2 使用内置 IMU去畸变并发布 `/Laser_map`、`/Odometry`；
3. 将三维地图投影为二维 `/map`；
4. 将 LIO 全局位姿适配为 `map -> odom`；
5. Nav2 使用二维 costmap，底盘局部速度仍来自 `/odometry/filtered`；
6. 建图完成后保存 PCD 与二维地图，导航模式切换为只定位。

### 8.2 Pace 备用路线

1. `bluesea2` 发布 `/scan`；
2. SLAM Toolbox 读取 `/scan` 和 TF，发布 `/map`、`map -> odom`；
3. 保存二维地图；
4. 导航模式关闭 SLAM Toolbox，启动 map_server + AMCL；
5. AMCL 发布 `map -> odom`。

### 8.3 Nav2 规划层

建议先完成 DWB 全向基线，再切换 MPPI：

```text
全局规划器  第一阶段 NavFn 或 SmacPlanner2D
局部规划器  第一阶段 DWB（vx、vy、wz 全向采样）
局部规划器  第二阶段 MPPI OmniMotionModel
速度链路    controller -> velocity_smoother -> collision_monitor -> /cmd_vel_safe
```

底盘外轮廓、最大加速度和制动距离尚未实测前，不给出虚假的最终 costmap footprint 或速度值。

### 8.4 任务层

任务节点只调用 Nav2 action，不直接发布电机速度。建议接口：

```text
输入   目标点列表、超时、重试次数、到达动作
状态   IDLE / NAVIGATING / PAUSED / RECOVERY / SUCCEEDED / FAILED
输出   当前目标、剩余目标、失败原因、导航反馈
```

键盘、任务和远程控制最终应进入同一速度仲裁和安全链路。

## 9. 构建、传输和启动

### 9.1 初始化外部源码

```bash
cd ~/ros2_ws
git submodule update --init --recursive
cp src/livox_ros_driver2/package_ROS2.xml src/livox_ros_driver2/package.xml
```

Livox SDK2 固定为 v1.3.1，安装过程见 `src/kiwi_slam/README.md`。SDK 的 build/install
产物不提交根仓库。驱动需要系统库存在 `/usr/local/lib/liblivox_lidar_sdk_shared.so`；
若该文件不存在，先执行 SDK 的 `cmake --install`，再执行 `sudo ldconfig`。

### 9.2 编译

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -r -y --rosdistro humble
# 工作区 colcon.meta 自动只为 livox_ros_driver2 传入 -DDISTRO_ROS=humble，驱动无需额外手工参数。
colcon build --symlink-install \
  --packages-up-to livox_ros_driver2 fast_lio kiwi_slam
source install/setup.bash
```

日常只改底盘或建图封装时执行 `colcon build --symlink-install --packages-select kiwi_base kiwi_slam`；
首次部署、修改接口或外部驱动后再执行上面的依赖构建。Livox SDK2 首次安装到 `/usr/local` 后不会
随每次工作区构建重复编译，只有 SDK 源码或系统安装路径变化时才重新编译并安装。

只修改本项目包时：

```bash
colcon build --symlink-install --packages-select kiwi_base kiwi_slam
source install/setup.bash
```

### 9.3 SCP 到工控机

```bash
scp -r \
  /home/ym/ros2_ws/src/kiwi_base \
  /home/ym/ros2_ws/src/kiwi_slam \
  a@192.168.66.119:~/ros2_ws/src/
```

首次需要外部源码时再传输 `src/FAST_LIO_ROS2`、`src/livox_ros_driver2` 和
`third_party/Livox-SDK2`。不传输 `build/ install/ log/`，不在文档持久化 SSH 密码。

### 9.4 启动

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

# Mid-360S 主路线
ros2 launch kiwi_slam kiwi_lio.launch.py

# Pace 二维备用路线
ros2 launch kiwi_slam kiwi_slam.launch.py use_rviz:=true

# 独立底盘 + C 板 IMU EKF
ros2 launch kiwi_base kiwi_base_ekf.launch.py
```

FAST-LIO2 将初始世界坐标系固定命名为 `camera_init`，该名称不代表系统依赖摄像头。
三维 RViz 应使用 `camera_init` 显示 `/cloud_registered` 和 `/Laser_map`。
工控机主路线默认使用硬件 OpenGL；远程桌面黑屏时再传入 `rviz_software_rendering:=true`。
