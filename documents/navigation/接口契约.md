# 上位机导航双人协作与接口契约

> 状态：第一版冻结草案
> 日期：2026-08-06
> 适用环境：Ubuntu 22.04、ROS 2 Humble、三轮 Kiwi 全向底盘
> 目标：让 A、B 可以并行开发，并通过稳定的 `odom` 边界联调。

## 1. 结论与文档入口

两个人不按“建图/定位”拆分，而按局部连续坐标 `odom` 拆分：

```text
人员  负责范围                         对外核心交付
A     机器人平台、传感器、状态估计     /scan、/odometry/filtered、odom→base_footprint
B     SLAM、地图定位、Nav2、安全速度链  map→odom、地图、/cmd_vel_safe、/software_estop
```

详细路线：

- [A：平台与状态估计路线](A平台与状态估计路线.md)
- [B：SLAM 与 Nav2 路线](BSLAM与Nav2路线.md)
- [总实施方案](../总实施方案.md)

本文件优先级高于个人路线中的接口示例。接口要变更时，必须先改本文件并由两人确认。

## 3. 冻结的坐标、单位和时间规则

### 3.1 ROS 对外坐标

所有跨包接口采用 REP-103：

```text
+x  机器人前方
+y  机器人左方
+z  机器人上方
+wz 绕 +z 逆时针
```

`/cmd_vel_nav`、`/cmd_vel_keyboard`、`/cmd_vel_selected`、
`/cmd_vel_smoothed` 和 `/cmd_vel_safe` 必须全部使用这一坐标。当前底盘已有的临时换轴、
轮序和电机符号只能封装在 `kiwi_base` 内部，不允许 B 增加第二套换轴节点。

### 3.2 单位

```text
线速度/加速度       m/s、m/s²
角度/角速度         rad、rad/s
轮输出轴角速度       rad/s
电机转子轴角速度     rad/s
时间戳              ROS Time，表示采样时刻而不是发布时刻
```

C 板当前 `motor_actual` 单位尚未实测冻结。若回传 rpm，A 必须先乘 `π/30` 转为电机轴
`rad/s`，再除以减速比得到轮输出轴 `rad/s`；ROS 话题中禁止继续传播不标单位的 rpm。

### 3.3 时间

- `/scan`、IMU 和轮反馈使用各自采样时刻；不能用 EKF 发布时刻覆盖源时间戳。
- 第一阶段允许 USB 接收时刻作为轮反馈近似采样时刻，但 A 必须记录延迟和抖动。
- 后续协议应增加 MCU 单调时间、反馈序号和累计轮角；不能静默修改现有 `0x3B` 字段。
- 两台计算机联调时使用同一时间源；使用仿真或 rosbag 时全系统统一 `use_sim_time`。

## 4. 唯一 TF 拓扑和所有权

冻结拓扑：

```text
map ──B：SLAM Toolbox 或 AMCL，二选一──> odom
odom ──A：robot_localization EKF────────> base_footprint
base_footprint ──A：robot_state_publisher──> base_link
base_link ──A：URDF/Xacro──────────────────> lidar_link
                                               imu_link
                                               wheel_link_1/2/3
```

规则：

1. `kiwi_base_node` 发布原始里程计消息，但不发布 `odom→base_footprint`。
2. 建图模式只允许 SLAM Toolbox 发布 `map→odom`。
3. 已知地图导航模式只允许 AMCL 发布 `map→odom`。
4. `base_footprint` 是二维导航基准；`base_link` 是机体几何和惯量基准。
5. 雷达消息的 `frame_id` 必须是 `lidar_link`，禁止写成 `map` 或 `odom`。
6. 每条 TF 只能有一个发布者；静态 TF 只由 URDF/robot_state_publisher 提供。

## 5. 冻结话题契约

### 5.1 A 发布，B 使用

```text
话题                    类型                         frame / child               频率起点   QoS
/scan                    sensor_msgs/msg/LaserScan    lidar_link                  约 7 Hz   SensorDataQoS
/odometry/filtered       nav_msgs/msg/Odometry        odom / base_footprint       50 Hz     reliable, depth 10
/tf                      tf2_msgs/msg/TFMessage       odom→base_footprint         50 Hz     TF 默认 QoS
/tf_static               tf2_msgs/msg/TFMessage       机器人静态树                启动时     transient_local
/diagnostics             diagnostic_msgs/msg/DiagnosticArray  无                 1 Hz      reliable
```

消息约束：

- `/scan` 的角度必须单调、量程单位为米、无效点使用 `inf`，时间参数与实测圈周期一致。
- `/odometry/filtered` 必须包含标准坐标下的 `vx`、`vy`、`wz` 和非零协方差。
- A 不向 B 暴露电机轮序、减速比或临时控制坐标。
- B 的 Nav2、SLAM、AMCL 统一使用 `base_footprint`、`odom`、`map` 和 `/scan`。

### 5.2 A 内部可观测话题

```text
话题                 类型                         约束
/wheel/odom_raw       nav_msgs/msg/Odometry        odom / base_footprint，标准 SI，不发布 TF
/imu/data_raw         sensor_msgs/msg/Imu          imu_link，角速度/加速度必须带协方差
/imu/data             sensor_msgs/msg/Imu          可选的方向滤波结果，不存在时不得伪造
/joint_states         sensor_msgs/msg/JointState   三轮位置 rad、速度 rad/s
```

当前代码默认发布 `/wheel/odom`。A 在接入 EKF 前必须迁移为 `/wheel/odom_raw`，或在评审后
统一修改本契约；不允许同时保留两个语义相同但无人确认的名字。

### 5.3 B 发布，A 使用

```text
话题                    类型                      坐标/语义                         频率/超时
/cmd_vel_nav            geometry_msgs/msg/Twist   REP-103，Nav2 原始控制输出        20 Hz 以上
/cmd_vel_keyboard       geometry_msgs/msg/Twist   REP-103，人工接管输入             20 Hz 以上
/cmd_vel_selected       geometry_msgs/msg/Twist   仲裁后的唯一速度源                20 Hz 以上
/cmd_vel_smoothed       geometry_msgs/msg/Twist   限速、限加速度后的速度            20–50 Hz
/cmd_vel_safe           geometry_msgs/msg/Twist   碰撞保护后的最终标准速度          20–50 Hz，100 ms 超时
/software_estop         std_msgs/msg/Bool          true=立即停车；false 不绕过硬件急停  10 Hz，300 ms 超时
```

`/cmd_vel_safe` 是 A/B 的控制边界。A 在 100 ms 内收不到新命令、收到非有限值、反馈超时、
串口断线或 `/software_estop=true` 时，必须主动向 C 板发送零速；不能依赖 B 持续发零。
`/software_estop` 使用 reliable、depth 10；A 启动后在收到首个有效 `false` 前保持停止，
300 ms 未收到心跳也按 `true` 处理。

## 6. 速度和安全链路

冻结的数据流：

```text
Nav2 controller ──> /cmd_vel_nav ───────┐
keyboard ─────────> /cmd_vel_keyboard ──┼─> 速度仲裁
software estop ─────────────────────────┘       │
                                               v
                                     /cmd_vel_selected
                                               │
                                      velocity_smoother
                                               v
                                     /cmd_vel_smoothed
                                               │
                                      collision_monitor
                                               v
                                       /cmd_vel_safe
                                               │
                         kiwi_base：超时/有限值/反馈联锁/硬件换轴
                                               v
                                   MCU watchdog + 物理急停
```

优先级固定为：物理急停/软件急停 > 键盘接管 > Nav2。仲裁实现可使用 `twist_mux` 或项目
自研节点，但输出话题和优先级不能改变。当前系统未安装 `twist_mux`，B 必须把依赖安装
或自研实现写入自己的交付记录。

## 7. 运行模式与 TF 发布者

```text
模式          map→odom 发布者      odom→base_footprint 发布者  速度来源
平台台架      无                    A/EKF 或测试替身             键盘
建图          SLAM Toolbox          A/EKF                        键盘
地图定位      AMCL                  A/EKF                        键盘或 Nav2
正式导航      AMCL                  A/EKF                        Nav2，经安全链
rosbag 回放   SLAM/AMCL 按测试目标  bag 或 A 的回放节点           默认禁用硬件输出
```

SLAM Toolbox 和 AMCL 不得同时运行。回放模式必须显式禁用串口写入，防止离线测试驱动实车。

## 8. 双向交付物

### 8.1 A 交给 B

1. 至少 3 分钟的 rosbag，包含 `/scan`、`/wheel/odom_raw`、`/imu/data_raw`、
   `/odometry/filtered`、`/tf`、`/tf_static` 和 `/diagnostics`。
2. 一份 `view_frames` TF 图和 `ros2 topic hz` 结果。
3. 三次纯运动记录：前进、左移、逆时针，每次包含命令与里程计曲线。
4. 反馈单位、轮序、减速比、轮径和 IMU 安装方向的签字记录。
5. 可一条命令启动的平台 launch；启动失败时保持零输出。

### 8.2 B 交给 A

1. Nav2 最大 `vx/vy/wz`、加减速度和 footprint 冻结值。
2. `/cmd_vel_safe` 与 `/software_estop` 的回放测试及超时测试。
3. 建图、定位、导航三个独立 launch，保证 `map→odom` 不重复。
4. 地图 `.yaml + .pgm`、Nav2 参数、RViz 配置和对应 rosbag/commit。
5. 人工接管、障碍停车、定位丢失、规划失败时的速度归零记录。

## 9. 推荐并行顺序

```text
阶段/时间       A 路线                                      B 路线
第 1 天         冻结轮序、单位、ROS 标准坐标；修复运动学测试  建包骨架、准备回放 launch 和假数据
第 2–3 天       /scan、/wheel/odom_raw、IMU、静态 TF          用 bag 跑通 SLAM/AMCL 基础配置
第 4–5 天       EKF、odom→base_footprint、平台 rosbag          DWB 全向参数、costmap、地图保存加载
第 6–7 天       超时/断线/estop/diagnostics                    速度仲裁、smoother、collision monitor
之后共同联调    实车轴向与里程计复核                           建图、重定位、单目标、临时障碍
```

B 在前五天都可以使用 rosbag 或测试替身并行推进；只有实车 DWB critic 和速度极限调参依赖
A 的 G1 交付。A 不应等待 B 完成 Nav2 才做 EKF 和安全测试。

```text
门禁  通过条件                                                        责任人
G0    接口文档冻结；标准坐标、话题、frame、单位无歧义                  A+B

```

G1 未通过时，B 可以开发和回放参数，但不要在实车上调局部规划器。

## 11. 当前项目与目标契约的差异

截至 2026-08-06，必须优先处理：

1. `kiwi_kinematics.cpp` 当前逆解轮序与正解/测试不一致，运动学测试失败。
2. 当前键盘和底盘使用临时控制坐标，尚未把 ROS 对外接口统一到 REP-103。
3. 当前默认话题是 `/wheel/odom`，目标契约是 `/wheel/odom_raw`。
4. `bluesea-ros2/params/*.yaml` 当前把雷达 `frame_id` 写成 `map`，必须改为 `lidar_link`。
5. `motor_actual` 的 rpm/rad/s 仍待实测冻结；当前配置默认按电机轴 rad/s 解释。
6. 当前协议没有反馈序号、MCU 时间和累计轮角，仅积分瞬时速度。
7. 当前上位机未启用命令超时、反馈联锁和软件急停。
8. 当前未创建 URDF/Xacro、EKF、SLAM 和 Nav2 项目包；`robot_localization` 尚未安装。

这些差异是路线任务，不应通过在 B 的 Nav2 参数中加入补偿来掩盖。

## 12. 接口变更规则

任何人修改话题名、消息类型、frame、单位、QoS、速度上限或 TF 发布者时，必须同时：

1. 修改本文件并写明兼容/迁移方案。
2. 更新对应参数、launch 和测试。
3. 提供能复现变更的 rosbag 或自动化测试。
4. 由另一人评审后合并。

未经评审，不允许通过 launch remap 临时制造第二套“实际接口”。
